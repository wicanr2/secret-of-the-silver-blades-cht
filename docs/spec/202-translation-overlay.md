## 1. 問題

中文化要在原版畫字的那一刻，把一行英文換成中文。原版照常執行、照常畫英文，轉譯層在放大畫布上的同一個位置蓋上中文。
這套機制與遊戲無關：**排版、定色、判斷疊字是否還有效、捲動、畫字**換一款遊戲照樣成立；
「哪個位址是印字常式、字串來源是哪個檔哪個偏移」才是遊戲專屬的，由呼叫端提供。

## 2. 規格（套件 `github.com/wicanr2/dosgolem/xlate`）

### 2.1 字型

- `type Font struct { W, H int; Glyphs map[rune][]byte; Name string }`：每字 H 列、每列 `(W+7)/8` bytes，MSB 在左。`Name` 由呼叫端設定，快照以它記字型（`LoadFont` 回傳空字串）。
- `LoadFont(path)`：檔案格式 `GOLEMFNT`（8 bytes）、u16 W、u16 H、u32 字數，之後每字 u32 碼點 ＋ u8 來源（呼叫端自訂）＋ 字模。
  長度對不上、magic 不對回錯。每字的來源位元組讀過即丟，不保存。

### 2.2 排版

- `Layout(text string, widths []int) ([][]rune, error)`：一個字元一格，依序填滿各行，`\n` 強制換行；放不下回 `ErrTooLong` 與截掉後的結果。

### 2.3 疊字

`type Stamp struct`：

| 欄位 | 意義 |
|---|---|
| `Key` | 呼叫端的識別（例：文本檔 key） |
| `X, Y` | 左上角，原版像素 |
| `Cells`、`CellW`、`CellH` | 格數與每格原版像素 |
| `Font *Font`、`GlyphX, GlyphY` | 字型與字模在放大後的格內的偏移（放大後像素） |
| `Text []rune` | 這一行要畫的字元 |
| `Transparent []bool` | 透明格：不填背景、不畫字、不列入定色與指紋（長度可短於 `Cells`，缺的當 false） |
| `SwapColors bool` | 定色時把背景與前景對調（見 `Frame`） |
| `State` | `Printing`（原版還在畫）、`Pending`（等定色）、`Shown` |
| `Transparent` 會被 `Frame` 與 `Add` 就地改寫 | 被別的東西蓋住的格子自動標成透明 |
| `FG, BG` | 定色後的 RGB |
| `Early bool` | 呼叫端加入時已知顏色、已填 `FG`、`BG`：`Draw` 在 `Printing`、`Pending` 也照這組顏色畫，不等定色（§2.3.1） |

`type Layer struct { Stamps []*Stamp; OnDrop func(*Stamp, string); W, H int }`（W、H 是原版畫面大小，0 當 320×200）：

- `Add(s)`：舊疊字被 s 的矩形**整個蓋住**才移除（原因 `overlap`）；只蓋到一部分時，被蓋到的格子標成透明
  （不畫、不列入指紋），狀態回到 `Pending` 讓剩下的格子重新定色；全部格子都透明時才移除。
  已顯示（`Shown`）的疊字這時**只重新定色**，各格指紋、失效計數與錨定格沿用，不拿下一幀重算：
  覆蓋常與換畫面在同一幀發生（dkk 查驗題答對後原版一次畫好冒險畫面，隊伍欄標題同時蓋到題目右端），
  重算的話壓在新畫面上的舊格子會被當成仍然有效，留成殘字。還沒顯示過的疊字照常在下一幀完整定色。
  原版會在一個框旁邊開另一個框（輸入檔名的面板蓋住訊息框右半），整筆移除會讓沒被蓋到的那半露出原版英文。
- `Replace(s)`：先以 `replace` 原因移除與 s 左上原點完全相同的舊疊字，再執行 `Add(s)`；用於同一文字輸出位置先後顯示不同長度內容。
- `Scroll(x0, y0, x1, y1, dy)`：左緣與右緣都在 `[x0, x1]`、上緣在 `[y0, y1)` 的疊字 Y ＋dy；移出框的移除（`scroll`）。橫向只超出一部分的疊字（例如另一套字型、位置剛好與框重疊的區塊）不搬。
- `Clear(x0, y0, x1, y1)`：依原版像素半開矩形使相交疊字失效；整筆被覆蓋時以 `clear` 移除，部分覆蓋時只將相交格轉為透明，剩餘格回到 `Pending` 重新定色（已顯示的同 `Add`，只重新定色、不重算指紋）。
- `Frame(indexed, rgb []uint8)`：`Pending` 的取矩形內非透明格的色號，出現最多是背景、第二多是前景（只有一種時兩者相同），
  RGB 取該色號在矩形內第一次出現的位置，**每一格各記一個 FNV-1a 64 位元指紋**，轉 `Shown`；
  - **`SwapColors`**：「出現最多的是背景」對一般的一行文字成立，但**字比底密的區塊會反過來**
    （字模填滿整條橫幅時，字的像素多於底）。這種區塊由呼叫端設 `SwapColors`，定色時把兩個色號對調。
    判斷哪一塊要設，是呼叫端看原版圖的事——這一層只認旗標，不猜。
  `Shown` 的**逐格**比對：某一格連續 3 次不同就把那一格標成透明（中間恢復一次就重新計數），
  全部格子都透明時整筆移除（`changed`）。
  逐格而不是逐行的理由：原版會在一行的一部分上面畫別的東西（輸入面板蓋住訊息框右半、狀態欄的值改寫標籤旁邊），
  整行失效會讓沒被蓋到的部分露出原版英文。
  - **錨定格**：定色時該格的原版像素不只一種色號（＝那一格有原文的墨跡）。定色時一起記下來。
    錨定格**全部**失效時整筆移除（`anchors`），不等其餘格子。
    理由：疊字存在的前提是「原版那段文字還在畫面上」，而這件事只有壓在墨跡上的格子看得出來。
    中文比原文寬時，多出來的格子壓在純色背景上，指紋永遠不變——原版把整段文字清掉之後，
    這些格子仍然「沒變」，於是整行中文瓦解成幾個留在畫面上的孤字。
    （實例：道具頁翻頁後藍色面板已清空，畫面上仍留著「上」「經」兩個字，
    因為「上限」「經驗」的錨定格都失效了，而第一格壓在純藍背景上。）
    沒有任何錨定格的疊字（整塊都是純色）照舊逐格判斷。
- `Draw(dst []uint8, scale int, missing func(rune)) bool`：dst 是放大後 RGBA（寬 W×scale）。每筆 `Shown`：非透明格填背景色；每格的字模以前景色畫在 `(格左上 ＋ GlyphX, 格左上 ＋ GlyphY)`；
  字模每個點畫成 `k×k`，k 由呼叫端透過 `GlyphScale` 決定（§2.4）。字型沒有的字呼叫 `missing`；半形與全形空白不畫。
  `GlyphX`／`GlyphY` 是放大後像素（呼叫端自己乘上 scale 的比例）；超出格子寬或高的點都不畫。
- `Stamp.Owner string`：建立這一筆的 watcher 的 Key（`203-baked-text-watchers`），一般疊字是空字串；快照要保存。
- `Frozen func(*Stamp) bool`（可為 nil）：回 true 的疊字在這次 `Frame` 不定色、不檢查指紋、失效計數不變。原版正在逐步搬動那一塊畫面時（訊息框捲動），中間狀態不能拿來判斷失效。
- `Snapshot() ([]byte, error)`、`Restore([]byte, fonts map[string]*Font) error`：疊字層存成 JSON（字型以 `Font.Name` 記），給逐步操作（規格 `201`）跨步保留。
  指紋與連續不同次數也一起存，否則還原後第一次 `Frame` 會誤判成畫面變了。`OnDrop` 不存（是呼叫端的 hook）。快照裡的字型名稱在 `fonts` 找不到時整批回錯。

#### 2.3.1 顯示中的色盤更新

狀態：READY，2026-10-02。證據入口為 `psychic_war_cht/docs/re/038-hd-theme-feasibility.md` §52，
本機 `workplace/hd/over-frontend-colors-v1-20261002.json`。原版先將兩個不同色號都映成黑色，
前兩行定色後才把色號15恢復白色；色號指紋不變，舊固定RGB導致中文前兩行保持黑色。已證實。

- Pending按原契約選背景／前景色號，另在記憶體保存所選色號。
- Shown只從仍可見且指紋與原版基準相同的格取RGB，更新相同色號的顏色；不存在該色號時保留先前RGB。
- 色盤變化不重新定指紋、不重置失效次數、不改透明格或錨定格。
- 快照格式與原版存檔不變。Restore保留既有FG／BG；第一次Frame若所有可見格均吻合，
  以相同定色及SwapColors規則重建記憶體色號。未吻合時不猜色號，原失效機制照常運作。
- 測試涵蓋黑色色盤恢復、SwapColors、失配格拒絕取色、快照及舊快照恢復；
  正常視窗三行中文及語言／HD切換須另驗，不以單元測試冒稱GUI完成。

### 2.3.1 提早顯示（`Early`）

需求來源：secret-of-the-silver-blades-cht #16（使用者 2026-10-22：降低先畫原版文字、再疊譯文的閃爍）。

量測（已證實，sosb-play 逐格截圖 7,501 格）：原版重畫隊員名單時，新疊字整個蓋住舊疊字，`Add` 立刻移除舊的；
新的要等原版印完、下一次 `Frame` 定色才轉 `Shown`。這中間合成畫面露出一格英文（第 14655 格整份名單、
「LOADING...PLEASE WAIT」各一格）。

- `Early` 為 true 的疊字，`Draw` 不看狀態：`Printing`、`Pending` 用呼叫端填的 `FG`、`BG` 畫背景與字模。
- `Frame` 的定色與指紋照常：`Pending` 轉 `Shown` 時以畫面實測的顏色覆寫 `FG`、`BG`。
- 預設 false，行為與前一版相同；只有呼叫端確知顏色（印字呼叫的參數帶色號）時才設。

### 2.4 字模放大倍率

`Stamp.GlyphScale int`：字模一個點在放大後畫布上佔幾個像素。0 表示 `scale / 3`（原本的 24 點字型配 8 像素字格、放大 3 倍）。
呼叫端保證「格寬 × scale ≥ GlyphX ＋ 字寬 × GlyphScale」；超出的點不畫。

#### 2.4.1 各倍率的變體字型

`Font.Scaled map[int]ScaledFont`（`ScaledFont{Font, X, Y}`）：某個輸出倍率改用另一份字模。`GlyphScale` 為 0 時，`Font.ForScale(scale)` 決定實際字型：有登記該倍率就用變體字型、字點 1:1、格內再偏移 (X, Y) 個實體像素；沒有登記則照上段規則（本字型、`max(1, scale/3)`、偏移 0）。`GlyphScale` 非 0 時呼叫端自行決定，不查變體。

- 變體不屬於 GOLEMFNT 檔案格式，也不進快照與字型雜湊；快照照舊以 `Font.Name` 引用底字型。
- `DeriveNearest(src, w, h)` 以最近鄰產生 w×h 變體，字模集合與 Name 不變。dkk 以它把 16×16 放成 22×22，3× 時置於 24 像素格偏移 (1,1)，同拯救地球 `manualThreeXFont`。
- 驗收：`TestFontForScaleVariant`（有、無變體與 GlyphScale 非 0 三種情況的實體像素位置）。

### 2.5 逐字迴圈的換行判斷

`type LineTracker struct`：`Hit(lin uint32, remain int, useRemain bool) (newLine bool)`。
印字常式常以迴圈頭逐字命中；位址等於上一次 ＋1（`useRemain` 時另外要 remain 等於上一次 −1）就是同一行，否則是新的一行。

### 2.6 閃現量尺（`FlashAudit`）

需求來源：secret-of-the-silver-blades-cht 規格 021（使用者 2026-10-22：完全不先露原版字或原版圖）。

量測「原版內容先原樣呈現、之後才被疊字或 HD 圖換掉」。只看呈現結果，不看疊字層內部狀態，所以疊字、HD 與日後任何覆繪機制共用。

- `NewFlashAudit(w, h, window int) *FlashAudit`：原版畫面 w×h（8 的倍數），窗 window 畫格。
- `Observe(frame int, indexed []uint8, base, out []uint8, scale int)`：indexed 是原版色號；base 是原版放大後的 RGBA，
  out 是同一畫格疊字、HD 合成後（面板之前）的 RGBA，兩者同為 `w×scale × h×scale`。逐 8×8 格：
  - 墨跡：格內兩種以上色號。
  - 原樣呈現：有墨跡，且 out 與 base 在這格的放大像素全部相同。記下畫格與格內色號的 FNV-1a 64 指紋。
  - 被改：out 與 base 在這格至少一個像素不同。若上次原樣呈現在 `(frame − window, frame)` 之內、指紋與現在相同，記一筆 `FlashEvent{Frame, Shown, CX, CY}`，並清掉這格的紀錄。
- `Events() []FlashEvent`、`Count() int`。

驗收（`xlate/flash_test.go`）：原樣呈現後下一格被改記一次；指紋不同（內容換了）不記；超過窗不記；沒有墨跡不記；同一次原樣呈現只記一次。

### 2.7 依原版內容重現譯文（殘影疊字）

需求來源同 §2.6。量測（已證實，sosb demo 戰鬥第 4535、5047 格）：原版把右側訊息區整塊重畫，同一段「HITTING FOR 19」英文回到原位；
呼叫端偵測到呼叫外的顯存寫入就移除疊字，下一則訊息才有新疊字，中間露一格英文（`FlashAudit` 記 55 格）。

原則：某處原版墨跡與一筆疊字定色時完全相同，那筆疊字的譯文就仍然適用，不管呼叫端是否已移除它。

- `Layer` 在每次 `Frame` 結束時記下「已顯示、有指紋、有錨定格」的疊字集合。
- `Draw`：上一次 `Frame` 之後被移除的這類疊字照常畫（合成用的原版畫面就是上一次 `Frame` 的，它們在那一幀仍有效），畫在現有疊字之前。
- `Frame`：上述被移除的疊字轉成殘影，最多保留 `GhostKeep` 個（預設 64，先進先出）、`GhostFrames` 次 `Frame`（預設 600）。
  殘影在這次 `Frame` 的**每一個**未透明錨定格指紋都與定色時相同才算有效；有效的殘影在 `Draw` 時畫（在現有疊字之前），無效就不畫，下次再判斷。
  沒有錨定格的疊字不轉殘影（整塊純色無從判斷原文是否回來）。
- `ForgetGhosts()`：清除全部殘影與上一幀集合。呼叫端在換語言、隱藏答案切換、視訊模式改變等「同樣原文應換成不同呈現」的時點呼叫。
- 殘影不進快照（與 `OnDrop` 相同，是執行期狀態）。

驗收（`xlate/ghost_test.go`）：疊字移除後同一幀照畫；原版同樣墨跡在之後的幀回來時畫出、內容不同時不畫；錨定格以外的格子相同不足以畫；
`ForgetGhosts` 後不畫；超過 `GhostFrames` 不畫。

### 2.8 保留呈現（`Hold`，HD 換圖用）

狀態：READY（2026-10-23，sosb 標題流程實測）。需求來源同 §2.6：HD 模式下不能先顯示原版圖。HD 圖面在整塊原版吻合時才換圖；
原版分幾幀畫完一張圖時，前幾幀的半張圖會原樣呈現。

- `NewHold(w, h, max int) *Hold`；`Apply(indexed, base, out []uint8, scale int, region func(cx, cy int, sum uint64) ([]uint8, bool))`：
  逐 8×8 格，這格有墨跡、out 與 base 相同（沒有被換掉）時問 `region(cx, cy, 格內色號指紋)`：
  - 回 `(hd, true)` 且 hd 不是 nil：呼叫端確定這格就是某張 HD 圖的這一格，直接畫 hd，不計保留次數、沒有上限。
  - 回 `(nil, true)`：可能是已知圖但有歧義；「內容與上一幀不同」或「上一幀已在保留」且連續保留未滿 max 次，就把上一幀的 out 複製回這格。
  - 回 `(_, false)`：不保留。
- 已開始保留的格不要求每幀都有變化：原版畫到一半停住時，半張圖也不露出。
- `Commit()`：新的一幀開始時呼叫，把這一幀最後一次 `Apply` 的結果定為「上一幀」。同一幀可以 `Apply` 多次（畫面、量尺、截圖），結果相同。
- `CellContent(indexed, w, cx, cy)`：與 `region` 收到的指紋同算法，呼叫端用它預先記下 HD 主題圖各格的指紋。
- sosb 的 `region`：這格內容等於某張主題圖在同一位置的墨跡格，也就是原版正在畫一張已知的圖；原版動畫與其他內容不受影響。
  只有一種 HD 畫面時直接畫它（demo 結束回 SSI 片頭時原版分段畫了超過 60 幀，保留上一幀會到上限後露出原版）；
  同一位置同樣內容對到多張不同 HD（三張標題共用的背景格）時才保留上一幀，上限 60 幀。

驗收（`xlate/hold_test.go`）：合成「一張兩格的圖分兩幀畫完、畫完才換 HD」，`FlashAudit` 0 次、中間那幀沒有原版的半張圖；
對照組不呼叫 `Apply` 時量到閃現；`region` 外不保留；連續變化超過 max 幀放行；畫到一半停住數幀仍保留；同一幀兩次 `Apply` 結果相同；
`region` 給出確定的 HD 格時直接畫、不受上限限制。

### 2.9 HD 鎖存（`Latch`）

狀態：READY（2026-10-23）。需求來源同 §2.6。sosb demo 戰鬥 3 倍＋HD 實測（`FlashAudit` 118 格）：戰鬥圖層（地形、怪物、頭身、效果、遭遇圖）
各自逐幀整件比對；法術光點蓋到龍的幾點、龍走到牆邊遮住牆格一角時，整件退回原版一幀，沒被蓋到的部分也露出原版。

原則：某格原版內容（色號）與色盤都和它上次被 HD 替換時完全相同，那次的 HD 畫面仍然適用。

- `NewLatch(w, h, keep, frames int)`；`Apply(indexed []uint8, pal uint64, base, out []uint8, scale int)`：逐 8×8 墨跡格，
  out 與 base 不同（這格被 HD 換掉）就記下（色號指紋、色盤指紋、倍率）→ 這格的 out；out 與 base 相同（圖層這幀沒換）而有記錄的指紋
  與現在相同，就把記下的畫面複製回 out。每格最多記 keep 筆（新的在前），`Tick()` 每幀呼叫，超過 frames 幀沒用到的移除。
- 只作用在圖層合成的結果上，文字疊字另由 §2.7 處理；`Forget()` 清空（換倍率、關閉 HD、視訊模式改變）。
- 同一幀多次 `Apply` 結果相同。
- 色盤指紋不同就不用：原版改色盤（閃光、淡入淡出）時圖層照規則不畫 HD，鎖存也不畫。

驗收（`xlate/latch_test.go`）：被換過的格在圖層停畫時照畫；原版內容變了不畫；色盤變了不畫；超過 frames 不畫；`Forget` 後不畫；
同一格兩種內容輪替時各自取回對的畫面。

### 2.10 隱藏的疊字（`Stamp.Hidden`）

狀態：READY（2026-10-23）。需求來源：sosb 換語言（主專案規格 015）。切到日、韓、英時，隊員名在新語言查不到譯文，
路徑 A 把這筆疊字移除露出原版；切回繁中時疊字已不在 `Layer`，隊員名停在原版英文，直到遊戲重印。

- `Hidden` 為 true 的疊字不畫（`Draw`、`DrawWithBackground`、`DrawChecked`），也不記成殘影（§2.7），原版照常露出。
- 其餘行為不變：仍在 `Layer.Stamps`，`Frame` 照常定色、記指紋、判斷失效並移除；覆蓋、清除、捲動的規則照舊。
  所以隱藏期間原版內容換掉時，這筆照常失效，之後不會把舊譯文畫回新畫面。
- 呼叫端換語言時：查不到或放不下的疊字設 `Hidden`，換回查得到的語言時清掉 `Hidden` 並換字。
- 快照保存 `Hidden`（JSON 欄位 `hidden`，`omitempty`，舊快照位元組不變）。

驗收（`xlate/layer_test.go`）：隱藏的疊字不畫、取消隱藏後照畫；隱藏期間底下原版改變時照常移除。

## 3. 驗收

1. 從 `psychic_war_cht` 搬來的測試全部通過：排版（7 字、18 字、32 字過長、`\n`）、捲動（右緣超出框的不搬）、重疊（整個蓋住才移除、部分重疊只遮格子）、3 幀逐格失效與恢復計數、定色、重疊移除、畫字與缺字回呼。
2. `GlyphScale` 與 `GlyphX／GlyphY`：16×15 字型、6×7 字格、scale 3、GlyphScale 1、偏移 (1,3)：字模左上點畫在格左上 ＋(1,3)；一格右緣之外不畫。
3. `LoadFont`：寫一個 2 字的 16×15 字型再讀回，字模相同；magic 錯、長度錯回錯。
4. `Snapshot`／`Restore` 往返後 `Draw` 出的 RGBA 逐位元組相同。
5. `LineTracker`：位址連續＋remain 遞減是同一行；remain 不遞減（`useRemain`）是新行；位址跳號是新行。
6. 透明格：透明格的色號不影響定色；只改透明格不會失效，改非透明格 3 次後失效（反向對照）；`Draw` 不碰透明格的像素。
7. `Frozen`：凍結期間指紋不同也不累計；解除後內容相同就繼續顯示。反向對照：不凍結時 3 次後失效。
8. `SwapColors`：同一塊像素設與不設各定色一次，`BG` 與 `FG` 互換；不設時仍是「最多的當背景」。
9. `Clear`：不相交疊字不變；部分清除只使相交格透明並重新定色；完整清除以 `clear` 原因移除。
10. `Replace`：同原點舊疊字以 `replace` 移除；不同原點疊字仍依 `Add` 的部分重疊規則處理。

## 4. 不做

- 印字常式的位址、字串來源換算、文本檔格式（遊戲專屬）。
- 可變寬字型、字距調整、雙向文字。
